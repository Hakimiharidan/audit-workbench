# Contributing

Thank you for helping. The rules below protect clients and keep results trustworthy.

## Never commit real data

- **Never commit real client or employer data** — not in data files,
  test fixtures, mappings, screenshots, issue text or commit messages.
- Only files generated by `tools/generate_synthetic.py` may live in `sample_data/`.
- Keep your own mappings and extracts in a gitignored folder (`private/`,
  `data/`, `input/`, `output/` are ignored). `*.csv` and `*.xlsx` are ignored
  everywhere except `sample_data/`.
- If real data is ever committed, do not just delete it in a new commit: tell
  the maintainer so history can be rewritten before anything is pushed.

## Engine rules

- No network calls, telemetry or AI services at runtime; no dependency that makes them.
- Nothing changes data silently: every placeholder conversion, coercion,
  rejected row and skipped test is logged and shown in the workpaper.
- The tool never fills a disposition, conclusion or sign-off field.
- Same input and parameters give the same `exceptions.jsonl`. Use fixed seeds.
- A new test must be addable as a folder (`test.sql` + `meta.yaml`) without
  engine changes. If yours needs an engine change, open an issue first.
- Money is `DECIMAL`, never floating point.

## Workflow

1. Add or change a test with its pytest coverage (`tests/`).
2. Run `pytest` — all tests, including the acceptance tests, must pass.
3. Keep dependencies minimal and pinned in `requirements.txt` and `pyproject.toml`.
4. Small commits with clear messages.
